🔬 The Six Approved Signals: Algorithmic Details & Field Mappings

Every signal operates completely independently and produces raw, unadulterated metrics. Signals are dispatched strictly based on field category.

1. Entity Changes Identity & Contact

Algorithm & Mechanism: Performs field-aware named entity recognition. For structured attributes (companies, contacts, locations, corporate IDs), it executes direct canonical entity state tracking. For body text, it extracts phone numbers via libphonenumber-js, emails via RFC 5322 regex, UK Companies House registration numbers (8-digit/2-alpha), and gazetteer-matched locations.

Use Case: Detects material real-world shifts: rebrands, company name drift, physical address moves, statutory ID deletions, and phone/email replacements.

Applicable Fields: companyName legalName phone email address country registration_number description

2. Embedding Semantic Similarity Conceptual Drift

Algorithm & Mechanism: Computes high-dimensional vector representations of natural language. Uses OpenAI text-embedding-3-small (or deterministic 128-dimensional term/n-gram hashing projection when offline) and calculates Cosine Similarity \(\cos(\theta) = \frac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\| \|\mathbf{v}\|}\) producing a score between 0.0 and 1.0.

Use Case: Identifies conceptual drift and business pivot in narrative text even when completely rewritten with different vocabulary. Ignores cosmetic paraphrasing.

Applicable Fields (Text Only): description summary tagline about products services aboutPage

3. TF-IDF + Cosine Similarity Distinctive Vocabulary

Algorithm & Mechanism: Calculates Term Frequency × Inverse Document Frequency: \(\text{TF-IDF}(t) = \text{TF}(t) \times \ln(1 + \frac{N}{\text{DF}(t)})\). Suppresses non-material stop words while exponentially weighting rare distinctive keywords (sector terminology, specialized products, trademarks). Evaluates vector cosine angle.

Use Case: Detects changes in specialized offerings or industry keywords while remaining immune to routine grammatical adjustments.

Applicable Fields (Text Only): description summary tagline business_description products_services_c

4. Jaccard Similarity Lexical Token Set

Algorithm & Mechanism: Evaluates set-based intersection over union of normalized word token sets: \(J(A, B) = \frac{|A \cap B|}{|A \cup B|}\). Independent of sentence grammar, word reordering, or punctuation insertion.

Use Case: Measures raw vocabulary retention between snapshots. When paired with embeddings, large divergences highlight structural copy edits vs genuine conceptual shifts.

Applicable Fields (Text Only): description summary title aboutPage

5. Number Changes Metrics & Quantities

Algorithm & Mechanism: Strips all URLs, query parameters (e.g. ?id=12345), tracking hashes, and session tokens. Extracts business numbers (integers, currencies £/$/€, headcounts, establishment years, percentages, unit metrics). Compares added vs removed numbers.

Use Case: Captures crucial commercial metric revisions: "28 years of experience" → "15 years", pricing tiers, workforce headcounts, and founding dates.

Applicable Fields: description summary founded_year employee_count revenue

6. Negation Changes Polarity & Operations

Algorithm & Mechanism: Detects polarity flipping terms (not, no, never, neither, ceased, closed, discontinued, halted, stopped, suspended, cannot) and extracts contextual sliding word windows around each occurrence.

Use Case: Catches operational shutdowns or state reversals that standard similarity misses: e.g. "Accepting new clients" → "Not accepting new clients".

Applicable Fields (Text Only): description summary homeContent termsPage
STRICT ALGORITHMIC BOUNDARY:
This pipeline explicitly forbids and excludes Levenshtein distance, SimHash, and MinHash. Character edit distance algorithms create false positives on minor typos and long URLs, while hashing heuristics obscure raw auditability.

⚡ Pipeline Flow: From Crawl to Actionable Decision

OLD COMPANY JSON + NEW COMPANY JSON
               │
               ▼
   [1. Deterministic JSON Diff]          (src/diff/deterministic_diff.js)
   • Pure JavaScript diffing (NO AI)
   • Traverses primitives, objects, arrays (ignores key order & whitespace)
   • Emits changed paths only
               │
               ▼
   [2. Value Normalization Layer]        (src/normalization/normalizer.js)
   • Resolves null vs "" vs "   " vs undefined -> NO_MEANINGFUL_CHANGE
   • Normalizes phones (E.164: 020 8368 1500 == +44 20 8368 1500)
   • Normalizes emails (case-folding) and strips URL tracking parameters
               │
               ▼
   [3. Field-Type Classification]        (src/config/field_analysis_config.js)
   • Resolves field category: IDENTITY | CONTACT | LOCATION | NUMERIC | TEXT | URL
   • Selects permitted signals strictly
               │
               ▼
   [4. Field-Specific Six Signals]       (src/signals/index.js)
   • Evaluates ONLY permitted signals
   • Missing values emit VALUE_ADDED or VALUE_REMOVED (no artificial 0 similarity)
               │
               ▼
   [5. Importance-First Scoring]         (src/scoring/scoring_engine.js)
   • Factual business changes (CRITICAL / HIGH) override generic similarity
   • London -> Manchester demands REVIEW regardless of embedding score
               │
               ▼
   Is change Ambiguous or Divergent?
          ├── NO  ──> Resolved Deterministically (AUTO_ACCEPT / REVIEW / IGNORE)
          └── YES ──> [6. AI Escalation Gate] (src/classifier/ai_escalation_classifier.js)
                      • Receives ONLY ambiguous field findings + identity
                      • LLM classifies: CONTENT_UPDATE | CORRECTION | BUSINESS_CHANGE
               │
               ▼
   [7. Dual Output Generation]
   ├── Client-Friendly Report: results/<domain>_client_report.json (Plain English)
   └── Full Auditable JSON:    results/<domain>_signal_analysis.json (All raw metrics)
